# Every expectation R12 requires, with the id it must carry.
#
# `specification:agent-charter-eval-cases` R12 states the rows as a table of kinds and matchers and
# names no ids. `T2` ("every row listed above is present in the right document, and every one of
# them is gating") cannot be checked against an unnamed row, and matching on a kind alone would let
# two different bounds satisfy each other. So the ids are fixed here, once, and both the document
# and the check read them from the same place.
#
# `T3` and `T4` also read this file — through `contract_expectation_id`, by the verb a row bounds,
# so no check spells an id as a literal of its own.
#
# ## Where the documents are
#
# The two documents are **AEP's**, not this repository's: `conformance/eval/<case>/
# expectations.trace.yaml`, replayed by that repository's own `task check`. `lib.sh` resolves them
# from `AEP_REPO`. The first column is therefore a *stage*, `decomposer` or `plan-reviewer`, and
# not a file name — both canonical files are called `expectations.trace.yaml`.
#
# ## Why the ids and matchers read the way they do
#
# Re-pinned 2026-09-04 against AEP 0.51.0. Before that this file named the ids of two
# documents that were never migrated here, and spelled the CLI `aep artifact …` while every
# recording under `../transcripts/` — which is what the documents are judged against, and which is
# evidence and is not rewritten — spells it `protocol artifact …`. Both halves are corrected to the
# canonical documents; the *substance* of every R12 row is unchanged, kind for kind and tool for
# tool. The mapping, so a reader can check that claim rather than take it:
#
#   R12 bound                                 was                            now
#   decomposer tool.absent Bash "… move"      never-ran-a-move               no-status-was-moved
#   decomposer tool.called Bash "… new"       created-through-the-cli        artifacts-were-created-through-the-cli
#   decomposer tool.called Bash "… validate"  validated-its-own-work         the-store-was-validated
#   decomposer permission.denied              nothing-was-refused            nothing-was-refused
#   decomposer env.agent_available            the-decomposer-was-offered     the-agent-was-offered
#   decomposer subagent.spawned               a-subagent-ran                 a-subagent-actually-ran
#   plan-reviewer tool.absent Bash "… move"   never-ran-a-move               nothing-was-moved
#   plan-reviewer tool.absent Bash "… new"    never-created-an-artifact      nothing-was-created
#   plan-reviewer tool.absent Bash "… relate" never-related-an-artifact      nothing-was-related
#   plan-reviewer tool.called Bash "…"        read-the-store-through-the-cli the-store-was-actually-read
#   plan-reviewer permission.denied           nothing-was-refused            nothing-was-refused
#   plan-reviewer env.agent_available         the-reviewer-was-offered       the-agent-was-offered
#   plan-reviewer subagent.spawned            a-subagent-ran                 a-subagent-actually-ran
#
# `terminal-record-clean` is new to this file and was always gating in both documents (R6's D8). It
# is listed because T2 now reads this file in both directions: a gating expectation the document
# declares and this file does not name is a bound nothing here checks, and it used to pass unseen.
#
# **R12's `tool.absent` over `Write` under `.engineering/planning` is deliberately absent**, and the
# decision is not this repository's. AEP's `conformance/eval/decomposer-charter/case.yaml`
# records it, in those words: *"Dropped on purpose … The charter grants `[Read, Grep, Glob, Bash]`,
# so `Write` is never offered and the row is true of every possible run — indistinguishable from a
# check that was switched off … a vacuous row is worse than a missing one because it reads like
# coverage."* That is R14's argument, and it is the same conflict `../README.md` recorded as T7's
# and left for the eval owner to settle. The owner settled it. This file follows.
#
# Format, tab-separated:
#   <stage>  <id>  <kind>  <tool>  <must-contain>  <severity>
# `<tool>` is `-` where the kind takes none. `<must-contain>` is a literal that must appear inside
# the expectation's `expect:` block; `-` where the kind's shape is the whole claim.
# Every row is `gate`: R12 says "at least these gating expectations", and T2 checks the word.
