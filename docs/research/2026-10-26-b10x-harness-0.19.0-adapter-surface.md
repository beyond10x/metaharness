## Why it moved

On 2026-10-24 a trial's harness arm failed with H9 `gap`: the installed loop was 0.19.0 and the
adapter was pinned to `["0.18.0"]`. The released metaharness 0.17.0 reproduces it against the
0.19.0 archive's executable: `metaharness run b10x --strict-version` exits 2 before the spawn with
*`--strict-version requires one of ["0.18.0"]; … reported 0.19.0`* (What ran, 4).

## What ran

1. `--version`, above.
2. `metaharness doctor b10x`, built from this change, with a scratch `HOME` holding the archive's
   executable in `.local/bin` and the environment cleared to `PATH=/usr/bin:/bin`. It exited 0 and
   printed that the binary is 0.19.0, on the adapter's pin, and that every flag the adapter sends
   is one the binary declares.
3. The golden loop record, made again by the procedure in
   `crates/metaharness-b10x/fixtures/golden/README.md` § *Recording it again*: the archive's
   executable, inside one `unshare --user --map-root-user --net --mount` namespace whose only
   interface is `lo`, in a private root, against harness's `fake_responses.py` at `13d72c06`,
   `flat-tool` scenario. `--version` and `run` both exited 0; the emulator recorded
   `has_authorization: false` on both requests; `credential_source` is `"none"`. This is
   `provider_emulated` evidence. The replay's expected stream moved only in `harness_version`.
4. `metaharness run b10x --strict-version --decisions observe --credentials none
   --model-endpoint <emulator> --model b10x-emulated`, in a network namespace whose only interface
   is `lo`, with `HOME` a scratch directory holding the archive's executable in `.local/bin`, once
   with the released metaharness 0.17.0 and once with this change's build. 0.17.0 exited 2 before
   the spawn (Why it moved). This change exited 0: `session.started` carries
   `harness_version: "0.19.0"` and `credential_source: "none"`, the stream holds one
   `tool.requested` and one `tool.result`, two turns, and `session.ended` with `is_error: false`;
   the emulator recorded `has_authorization: false` on both requests.
5. This workspace's suite at the pin. It compiles harness's library crates at `13d72c06` and
   exercises them in-process; that is evidence about the library at the commit, not about the
   released binary.

  orchestrator's word, as on 0.18.0.
- **The deadline itself.** No call ran long enough to reach 10000 ms; `deadline_reached: true` and
  its `note` were not observed.
