# codex-cli 0.160.0 app-server: a caller's catalogue, driven once on a login

Status: 2026-10-29. One live run of `metaharness run codex --catalogue` against codex-cli
**0.160.0** (tag `rust-v0.160.0`, `a956835`) on the operator's ChatGPT login; everything else here is
credential-free. It is the evidence for `story:codex-catalogue-on-app-server` and design amendment
a66 § 6. Labels: **observed** (the live run shows it), **free** (a run against a fixture provider on
127.0.0.1, no credential), **read** (source at the tag, not driven).

## 1. The run (observed)

```console

  --catalogue crates/metaharness-tools/tests/fixtures/caller-catalogue.yaml \
  --credentials operator-login \
  --frame crates/metaharness-protocol/fixtures/golden/metaharness-frame-canonical.json \
  --hermetic on --strict-version --cwd <work> --retain-dir <dir> \
```

  copied it into the scratch `CODEX_HOME` as on every `operator-login` run.
- `<work>` held `note.txt`, one line: `catalogue-probe-line-4b2e`.
- The canonical frame admits `file.read`, so the frame decided the call.

## 2. What the model was offered (observed)

The model request in the rollout trace has **no top-level `tools`**. The first input item is
`{"type":"additional_tools","role":"developer"}`, with three namespaces:

| namespace | tools |
|---|---|
| `functions` | `exec` (custom), `wait`, `request_user_input_async` |
| `clock` | `sleep` |
| `collaboration` | `followup_task`, `interrupt_agent`, `list_agents`, `send_message`, `spawn_agent`, `wait_agent` |

`fs_read` and `fs_stat` are not offered directly. `exec`'s description declares the nested tools a
script may call: `fs_read`, `fs_stat` and `clock__curr_time`. No image generation, apps, web search,
skills or shell tool appears.

So the catalogue was not the whole offer, and the event stream named a tool outside the catalogue
(`exec`, seq 11, the rollout's record of the code cell). Both contradict a66 as first written. Every
effect on the workspace still went through the catalogue: the only file access was the nested
`fs_read`, which arrived as `item/tool/call` and was decided by the frame.

## 3. Where the extra tools come from (read, then free)

The model's entry in the vendor's model catalogue decides them. The entry for `gpt-6.1-sol` in the
operator's own model cache (fetched by the operator's codex, not by this run) reads `tool_mode:
code_mode_only`, `multi_agent_version: v2` and `experimental_supported_tools:
[send_user_message_async, clock]`. At the tag:

- `requested_tool_mode` takes the model's `tool_mode` before any feature (`core/src/tools/mod.rs:75-96`);
- the model's multi-agent version wins unless `[agents] enabled = false` overrides it
  (`core/src/config/mod.rs:1586-1593`, `:1606-1613`). `features.multi_agent = false`, which a66
  set, does not;
- `request_user_input_async` is offered to a model whose entry names it or its old name
  `send_user_message_async`, and no config key gates it (`core/src/tools/spec_plan.rs:1178-1202`);
- `clock__curr_time` is registered for a model that names `clock` (`:1225-1233`), and `sleep` also
  needs `features.sleep_tool`, on by default (`:1234-1250`; `features/src/lib.rs:978-983`).

**Free.** That entry, given to codex as `model_catalog_json` with `model = "gpt-6.1-sol"` and the
fixture provider, reproduced the live request's namespaces and tools exactly. Adding `[agents]
enabled = false` and `[features] sleep_tool = false` left `functions` (`exec`, `wait`,
`request_user_input_async`) and removed `clock` and `collaboration`, with `--strict-config`
accepted. The same two keys passed `--strict-config` at 0.153.4. a66 now writes both. **That they
remove the same tools on a login is unverified**: this was the one live run.

What stays has no config switch at the tag. `features.code_mode_host = false` makes code mode
unavailable (`core/src/thread_manager.rs:558-564`), and a `code_mode_only` model then "fails
closed" (`core/src/tools/code_mode/mod.rs:108-118`), so it could call no tool at all.

## 4. What metaharness does with it

- The launch attestation on the catalogue route names these tools among its `ambient_inputs`, and
  `offered_tools` stays the catalogue: the rollout lists no built-in, so the record cannot show more.
- A code-mode call has two ids. The rollout records the `exec` cell under the model's id, and the
  live call carries `exec-<uuid>`. The record is described under `seam: none`, as every record is.
- Not done: removing `exec`, `wait` or `request_user_input_async`, or hiding the `exec` record from
  the stream. The first two have no switch; the third would drop a call the vendor made.

## 5. Not verified

- 0.153.4 on any login: only the fixture provider was driven there.
- Whether `request_user_input_async`, if called, arrives as a server request metaharness refuses,
  or as something else.
- What a spawned `collaboration` agent would have been offered: none was spawned, and a66 now
  removes the namespace.
