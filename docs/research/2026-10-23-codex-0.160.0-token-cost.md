# codex-cli 0.160.0: where the extra tokens a run come from

Status: read on 2026-10-23 against codex-cli **0.160.0** and **0.153.4**, with **no paid run, no login and
no credential**. It is the evidence for `story:codex-0-160-0-token-cost` and amendment a55. Labels as in
`2026-10-23-codex-0.160.0-record-surface.md`: **observed** (a credential-free run here shows it),
**trial** (read from the token records of a takt trial someone else ran), **inferred** (neither).

## The question

takt trial cycle 2026-10-23-54b8dd83 (takt 0.10.1, metaharness 0.15.0, scenario 1) capped every run at
85088 tokens, the saved maximum of the 0.153.4 baseline. Codex 0.160.0 ran 0/2 with its default model
gpt-6.1-sol (85944, 85794) and 0/2 with gpt-6-astra (85462, 85468). On 0.153.4 with gpt-6-astra it ran
4/5, median 84989. Is the increase in what metaharness sends, and can metaharness remove it?

## 1. What the trial spent, step by step (trial)

The last `token_count` record of each step's rollout, comparing the x101 median (0.153.4, 5 runs)
with the x103 mean (0.160.0, 2 runs). Both used gpt-6-astra, and every rollout records its `cli_version`:

| step | model calls | input tokens | output tokens | reasoning tokens |
|---|---|---|---|---|
| tests.write | 2 | 33116 → 33313.5 (+197) | 394 → 392.5 | 0 → 0 |
| implementation.edit | 2 | 34120 → 34303.5 (+183) | 315 → 304 | 0 → 0 |
| change.handover | 1 | 17023 → 17109 (+86) | 38 → 42.5 | 0 → 0 |
| run | 5 | **+466** | ≈ −9 | 0 |

The whole increase is input, about +93 tokens a model call. The model's output does not change.

The items the step-9 rollouts record are 399 bytes **smaller** on 0.160.0. The `<recommended_plugins>`
list, fetched from the `openai-curated-remote` marketplace, moves from the first user item into the
first developer item, and the system skill `plugin-creator` is no longer listed. `base_instructions` is
21483 bytes on both.

## 2. What the same launch sends offline (observed)

The native fixture's `actual_codex_reports_terminal_answer_model_and_failure_from_fixture_provider`
ran each binary under `unshare -rn`, with loopback only, `CredentialSource::None`, and the fixture
provider on 127.0.0.1. It records the request bodies the binary sent. Per model, `MODEL` in
`crates/metaharness-codex/tests/native_fixture.rs:31` was set to the trial's models in a scratch build
and not committed. The first request with gpt-6-astra, in bytes of JSON:

| `input` item | 0.153.4 | 0.160.0 | delta |
|---|---|---|---|
| `additional_tools` (developer) | 21275 | 21345 | +70 |
| base developer instructions | 21617 | 21776 | +159 |
| skills and permissions (developer) | 4478 | 3541 | −937 (`plugin-creator` gone) |
| the other four items | 4224 | 4224 | 0 |
| total | 51602 | 50894 | **−708** |

With gpt-5.5, the fixture's own model, the body is 177 bytes smaller on 0.160.0. Its `instructions`
carry a different built-in personality paragraph, consistent with record-surface § `personality`. The
model gpt-6.1-sol is not in 0.153.4's catalogue, and that binary falls back to the older wire shape
(`instructions` and `tools` as top-level fields), so the two are not comparable for that model.

## 3. Attribution

- Not in the launch metaharness writes. The same `plan_launch` output gives a **smaller** first request
  on 0.160.0 (observed).
- Not in output or reasoning (trial).
- **Inferred, unverified:** the ~93 tokens a call are content that appears only with network access,
  in the tool list or a fetched model catalogue. The 0.160.0 binary contains the `remote_models`
  feature name. Showing it requires a networked run against the real provider, which this work does
  not make.

## 4. What it means for a cap

+466 tokens on 84989 is +0.55%. The trial's cap was 85088, 99 tokens (0.12%) above the 0.153.4 median.
A consumer that caps at a 0.153.4 baseline's maximum stops a 0.160.0 run for a difference metaharness
does not produce and cannot remove offline. Decision (`b10x-chef-orchestrator`, 2026-10-23, option A):
keep the 0.160.0 pin, and takt rebases its cap for 0.160.0 arms. Amendment a55 records it.
