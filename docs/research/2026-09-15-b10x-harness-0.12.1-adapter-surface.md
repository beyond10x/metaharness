# b10x-harness 0.12.1 adapter surface

Status: verified on 2026-09-15 from **one paid `metaharness run b10x` observation** against
`b10x-harness 0.12.1`, except where labelled unverified. It is the evidence
`metaharness-b10x::PINNED_VERSIONS` and `HARNESS_REVISION` moved on — `0.10.2` /
`c1493a79331f315cac24aa3818ddaa1eb41c8b25` → `0.12.1` /
`90f10a4314c1c630691c85e812bd8d5d23d73fcc` — and it is dated, on a8's rule: the rows below name
the binary they were read from and are not inherited by a later release.

## Why it cost a run

The pair is the AEP eval's provenance check for an *installed* binary
(`crates/metaharness-aep-eval/src/lib.rs`, `validate_native_pin`), not the Cargo build pin, and the
Cargo pin moved to `0.12.1` on 2026-09-15 without it (`CHANGELOG.md`, `[Unreleased] / Changed`).
Moving this pair without re-observing the adapter's version-specific claims would have made
invariant 4 a claim about a binary nobody had read. Reading the code did not establish the two
findings below; the run did.

## Verified on 0.12.1

- **The terminal event is unchanged**: `{"kind":"finished","stop":{"kind":"completed"},"turns":2}`,
  which the adapter reads into `session.ended` `subtype: completed`, `terminal_reason: completed`,
  `num_turns: 2`, followed by `stream.closed` `reason: completed`.
- **Every record kind the run emitted is read.** `started`, `rates`, `turn-started`,
  `tool-arguments-delta`, `usage`, `cost`, `tool-requested`, `tool-completed`, `text-delta`,
  `finished` — **zero `opaque` lines**. `rates` and `tool-arguments-delta` emit nothing by
  design (`seam.rs`, the deliberately-silent arm); `cost` is folded into the run total.
- **`cost` still arrives a line after the `usage` it prices**, so `Usage::cost_usd` stays `None`
  and the figure is stated once on `session.ended`. The two `cost` lines were 14,879 and 2,602
  micro-USD and their sum is the `total_cost_usd` above.
- **The adapter's whole emitted flag set is declared by the binary.** `metaharness doctor b10x`
  against `0.12.1` → exit 0, both rows green, including *"every flag the adapter sends is one the
  binary declares"*.
- **`credential_source` reads `oauth:file`** off the record rather than off the launch.
- **The adapter contract is unchanged by the move except for who it is about.**
  `crates/metaharness/fixtures/golden/contract-result-b10x.json` was regenerated deliberately
  through `regenerate_the_contract_records`: `provider` `b10x 0.10.2` → `b10x 0.12.1`, and
  `checked: 7`, `failed: 0`, `breaking_changes: 0` all unchanged, claude and codex byte-identical.
  A consumer building against those bytes is reading about a different binary now, which is what
  `provider` is for. The gate caught this rather than a person remembering it.
- **`tool-requested` now carries its own `operation`** (`"operation":"file.read"`), which the 0.9.1
  capture does not. The adapter's `operations` row agreed with it on this run.
- `started` carried three `context` entries against the 0.9.1 capture's two: an
  `environment.execution` entry is present. Not otherwise examined.

## What the run found, and what each cost

- **`usage.cache_creation_input_tokens` was being dropped.** 0.12.1 emits it — 2,183 and 132 on the
  two `usage` lines — and `seam.rs` hardcoded `None`, which under invariant 3 reads as *nobody
  found out*. Somebody has now. **Fixed in this change**: the field is read, and an older loop's
  silence still reads `None`.
- **`b10x-harness` is no longer without an MCP client, and the adapter still says it is.** 0.12.1
  publishes `--mcp-profile` and `--mcp-registry` (`b10x-harness run --help`, read 2026-09-15) and
  writes an `mcp` field in `started`, which the 0.9.1 capture does not carry. `mcp_servers` is a
  hardcoded `Some(vec![])` justified by the standing fact that this harness has no such client —
  a justification `0.12.1` has retired. **Not changed here, deliberately**: the run observed the
  field only as `[]`, so the shape of an element is unestablished, and guessing it is the move
  this adapter refuses everywhere else. The stale claims in `lib.rs` and `seam.rs` are corrected to
  say what is true and what is owed.

## Unverified on 0.12.1, and labelled so

- The golden sample in `crates/metaharness-b10x/fixtures/golden/` is still `b10x-harness 0.9.1`'s
  bytes; `metaharness conformance b10x` warns `golden-version-pair` accordingly. That warning
  predates this pin move (it read 0.9.1-vs-0.10.2 before) and is not closed by it.
- No confinement was declared, so the run took the read-only catalogue
  (`file_read`, `dir_list`, `search`, `find`) and published no `run` entry. Nothing here says
  anything about 0.12.1's substrate behaviour, its approver, its hooks or its withholding.
- No `withheld`, `skills`, `agents`, `toolchains` or `profiles` entry was non-empty on this run, so
  none of those mappings was exercised against `0.12.1`.
- The `driven` and `native` eval arms were not run. This is the smallest recorded run, not a walk.
