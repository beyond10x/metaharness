# Story: One page renders two `trace-ir/1` streams side by side

## Outcome

A reader opens one static page with two runs and sees them aligned — state by state, call by call — with refusals, timings and cost per column, and a marker where the two diverge.

## Context

The bench's first deliverable is *both stacks on one corpus*, and the operator asked to visualise the event stream side by side (2026-09-02). The viewer reads `trace-ir/1` only, so a run from any adapter renders the same.

## Acceptance

- A static HTML page (no server) loads one or two `trace-ir/1` documents and renders columns: state entries, tool calls with decision, refusals, per-step duration, cumulative cost.
- Alignment follows the design page's rule; a step present in one run and absent in the other is shown as a gap, not skipped.
- The page is generated by `metaharness project --html` or a sibling verb, and the bench site embeds it.
- The two recorded `evals/aep` runs render as the fixture, checked in `task docs:build`.

## Out of Scope

Live rendering of a running session; interactivity beyond expand/collapse.

## Ambiguities

- `requires-stakeholder-input` — the alignment rule (see the epic). Decides: metaharness owner.
